#### The request

> "reorganize the button sizes, text size and create a pattern ... something too small and
> others too big ... standard of mobile development, grid, text, buttons all types"

#### Reading of it

- This is not a redesign. Colors, JetBrains Mono, layout and desktop stay as they are.
- What is missing is a **rule**: one small set of sizes that every page uses on mobile, so the
  same kind of thing (page title, primary button, chip, meta text) looks the same everywhere.
- "Too small" = 8–10px text and 21–31px tall tap targets. "Too big" = 32–40px page titles,
  a 525px-tall empty book slot, and 44px boxes wrapped around 11px text.

#### Proposal (approved; questions A-C still open)

Approach **A** (decided by João): CSS custom properties are the token system. Each token is defined
once in `:root` in `src/index.css` with its **desktop** value, and redefined with its **mobile** value
inside `@media (max-width: 768px) { :root { ... } }`. Inline styles use `var(--token)` and follow the
breakpoint with no JS. The "desktop" column is the most frequent current value for that role in the
inventory; the numbers in the tables below were approved by João.

##### Type scale (`--fs-*`, `--lh-*`)

| Token | Desktop | Mobile px / line-height | Use | Mobile replaces |
|---|---|---|---|---|
| `--fs-xs` | 10 | 11 / 1.3 | uppercase section/stat labels, tags, dock labels, badges | 8, 9, 10 |
| `--fs-sm` | 11 | 12 / 1.5 | meta: dates, counters, secondary lines | 10.5, 11, 12 |
| `--fs-base` | 13 | 14 / 1.6 | body text, buttons, chips, list rows | 13, 14, 15 |
| `--fs-input` | 13 | 16 / 1.4 | every `input`/`textarea` (iOS no-zoom) | 12, 13, 15 in inputs |
| `--fs-lg` | 15 | 17 / 1.35 | card and section titles, lesson prose | 15–19 |
| `--fs-xl` | none dominant | 22 / 1.25 | page title (one per page) | 16, 19, 20, 24, 26, 32, 36, 40 |

Big display numbers (rank 28, streak 20) stay as-is: they are numbers, not text. Dock labels use
`--fs-xs` = 11 (approved; each dock slot is ~67px and "Dashboard" at 11px is ~59px).

##### Spacing grid (`--sp-*`)

Base unit **4px**. Steps `--sp-1..--sp-7` = 4, 8, 12, 16, 20, 24, 32 (same on desktop and mobile). Gutter stays 20 (`MOBILE_GUTTER`).
Gap inside a control/row: 8. Between controls: 8–12. Between cards: 12. Between sections: 24 (32 for
page-title → content). Off-grid values (2, 3, 5, 6, 7, 9, 10, 14, 18, 22, 28, 36) map to the nearest step
when a page is migrated. `letterSpacing` and `lineHeight` collapse to the line-heights in the type table.

##### Controls (`--ctl-*`, heights)

| Token | Control | Desktop | Mobile height | Text | Padding-x | Radius | Mobile replaces |
|---|---|---|---|---|---|---|---|
| `--ctl-primary` | primary button (one per screen) | 40 | 48 | base 600 | 20 | md | 32, 44, 50, 52 |
| `--ctl-md` | secondary / ghost button, input, select, tab | 32 | 44 | base (input: `--fs-input`) | 16 / 12 | md | `.btn` ~30, `btnGhost` 30, 32, 40 |
| `--ctl-chip` | chip / pill (filter, mode tab) | 28 | 36 visible | base | 14 | pill | 28, 31, 44 |
| `--ctl-icon` | icon button (square), icon 20 | 32 | 44 | — | 0 | md or 50% | 17x21, 22x22, 26x26 |
| `--ctl-row` | tappable list row (min-height) | 44 | 52 | base + sm meta | 16 | lg | 31, 44 |
| `--ctl-tag` | tag (not tappable) | 18 | 20 | xs | 6 | sm | 10px tags at 18–20 |

Back links ("← cursos") use `--ctl-md` as min-height (was 21px). Minimum touch target **44x44**
(HIG / WCAG 2.5.5); 36px chips sit in rows with ≥8px spacing (WCAG 2.5.8 spacing exception).

##### Radius (`--radius-*`)

`--radius-sm` 4 (tags), `--radius-md` desktop 6 / mobile 8 (controls), `--radius-lg` desktop 8 / mobile 12
(cards, sheets, panels), `--radius-pill` 999 (pills, dock). Mobile replaces 1, 2, 3, 5, 6, 7, 9, 10, 14, 16, 20, 22.

##### Icons

16 inline with text, 20 in icon buttons and dock (`--icon-sm` / `--icon-md`; SVG `width` attributes
become `style={{ width: 'var(--icon-md)' }}` only where touched). Replaces 9–14, 17, 18, 22.

##### Implementation rules

1. **PR 1 adds tokens only.** Nothing references them yet, so no visual change anywhere.
2. A call site migrates to `var(--token)` **only if its current desktop value equals the token's desktop
   value**: then desktop is pixel-identical and mobile picks up the media-query value.
3. Desktop outliers (e.g. page titles: no dominant desktop size) keep their literal on desktop with the
   existing pattern `isMobile ? 'var(--fs-xl)' : 40`. Every migrated page except StoreItemPage and
   LoginPage already has `isMobile`. Open question C: alternatively add per-role desktop tokens, which would
   grow the token count.
4. Shared classes (`.btn`, `.tag`, `.stat-label`, `.section-label`, `.tab-item`, `.diff-badge`,
   `.sheet-item`) get their mobile values from the tokens. `.tag`, `.stat-label`, `.section-label`,
   `.diff-badge` (10 = `--fs-xs`) and `.sheet-item` (13 = `--fs-base`) match the desktop defaults directly;
   `.tab-item` and `.sheet-item` only render on mobile; `.btn` (12px, ~30px tall) does not match, so its
   mobile values go in a `.btn` override inside the media query.
5. `src/lib/layout.ts` keeps JS geometry (`MOBILE_GUTTER`, `DOCK_HEIGHT`); `--gutter` mirrors 20 in CSS
   only if a CSS rule needs it.
6. **No global touch-target floor.** Measured in-scope (excluding Chats/Profile): 25 controls under 44px,
   22 under 32px, all from ~15 call sites (Dashboard 8, Store 10, Config 4, Courses 2, Books 1). A blanket
   `button, a { min-height: 44px !important }` would also hit inline text links, the dock and tags, so the
   fix goes at the source. The existing scoped `.cfg-ctrl` rule (`index.css:205-208`) is replaced by tokens.

Rejected alternatives: **B** shared `Button/Chip/Input/Text` components (more code and churn, decided against).
**C** global `!important` CSS floor (hits links/tags/dock, hides call sites).

#### Design

##### Surfaces and tone (applies to both screens)

- At most **two raised surfaces per screen** for the NEW blocks (`--bg-card` + 1px `--border` + `--radius-lg`): on the Dashboard the status card and the next-action card. Everything else is a heading plus rows on `--bg`, separated by 1px `--border` lines.
- **Exception, by João's choice:** the Dashboard greeting and the Profile cover/identity block keep their current look (cover image, frosted identity backdrop, ring). The rules below apply to everything new, not to these two things.
- No emoji as icons, no gradients, no glow or `text-shadow`, no frosted glass, no coloured accent stripe on cards, no per-section fade-in.
- Motion only in response to a tap: expand/collapse and readout change.
- Sizes only from the scale tokens (`var(--fs-*)`, `var(--ctl-*)`, `var(--sp-*)`, `var(--radius-*)`). One justified exception: heatmap cells (data marks, not tap targets).
- Section labels use the app's existing `.section-label` style.

## Plan: Part 1 (UI scale)

**Goal:** One small CSS-variable scale (type, spacing, controls, radius, icons) that every page uses on mobile (<= 768px), with desktop pixel-identical.

**Architecture:** Tokens are defined once in `:root` of `platform/frontend/src/index.css` with their desktop value and redefined inside `@media (max-width: 768px) { :root { ... } }`. Inline styles and shared classes use `var(--token)`, so they follow the breakpoint with no JS. A call site migrates to a token only when its current desktop literal equals the token's desktop value; otherwise it uses `isMobile ? 'var(--token)' : <literal>`.

**Tech Stack:** React 19 + Vite + TypeScript, inline styles + `index.css`, `node --experimental-strip-types --test` for the token guard test, Playwright MCP for measurements.

**Spec:** `docs/superpowers/specs/2026-10-10-mobile-ui-scale.md`

#### Global Constraints

- Scope is viewports `<= 768px` (`MOBILE_QUERY`). Desktop stays pixel-identical.
- No redesign: same colors, JetBrains Mono as the only font, same layout (the one layout change is the Store sidebar stacking in Task 8).
- Tokens only through CSS custom properties. No shared `Button/Chip/Input/Text` components. No global `!important` touch-target floor: undersized controls are fixed at their call sites.

**Goal:** A mobile-only Dashboard and Profile built from a small set of reusable blocks in `platform/frontend/src/mobile/`, with desktop untouched.

**Architecture:** `DashboardPage` and `ProfilePage` keep their desktop bodies (renamed `DashboardDesktop` / `ProfileDesktop`) and gain a one-line selection wrapper that renders `DashboardMobile` / `ProfileMobile` under 768px. A mobile page is an ordered list of independent sections; each section receives one data slot (`status`, `data`, `retry`) from a page-level hook and renders loading, empty and error itself through `SectionState`. All sizes come from the scale tokens in `index.css`. Logic that can be tested without a DOM lives in dependency-free `.ts` modules covered by `node --test`; a source-contract test guards the folder.

**Tech Stack:** React 19 + Vite + TypeScript, inline styles with CSS variable tokens, `node --experimental-strip-types --test`, Playwright MCP for measurements.

**Spec:** `docs/superpowers/specs/2026-10-11-mobile-dashboard-profile.md`

```ts
export interface HeatmapDay { total: number; katas: number; books: number; courses: number }
export interface HeatCell { date: string; data: HeatmapDay; isToday: boolean; inRange: boolean }

const EMPTY: HeatmapDay = { total: 0, katas: 0, books: 0, courses: 0 }

export const LEVEL_COLOR = [
  'rgba(255,255,255,0.05)', 'rgba(34,211,238,0.30)', 'rgba(34,211,238,0.52)',
  'rgba(34,211,238,0.74)', 'rgba(34,211,238,0.93)',
]
export const TODAY_EMPTY = 'rgba(34,211,238,0.13)'

export function levelOf(total: number): 0 | 1 | 2 | 3 | 4 {
  if (total <= 0) return 0
  if (total >= 4) return 4
  return total as 1 | 2 | 3
}

// Weeks start on Sunday. The last week is padded with nulls after today.
export function buildWeeks(heatmap: Record<string, HeatmapDay>, today: Date, weekCount: number): (HeatCell | null)[][] {
  const end = new Date(today)
  end.setHours(0, 0, 0, 0)
  const gridStart = new Date(end)
  gridStart.setDate(end.getDate() - end.getDay() - (weekCount - 1) * 7)

  const weeks: (HeatCell | null)[][] = []
  let week: (HeatCell | null)[] = []
  const cur = new Date(gridStart)
  while (cur <= end) {
    const key = cur.toISOString().split('T')[0]
    week.push({ date: key, data: heatmap[key] ?? EMPTY, isToday: cur.getTime() === end.getTime(), inRange: true })
    if (week.length === 7) { weeks.push(week); week = [] }
    cur.setDate(cur.getDate() + 1)
  }
  if (week.length) {
    while (week.length < 7) week.push(null)
    weeks.push(week)
  }
  return weeks
}

export function describeDay(date: string, data: HeatmapDay): string {
  const when = new Date(date + 'T12:00:00').toLocaleDateString('pt-BR', { weekday: 'short', day: 'numeric', month: 'short' })
  if (data.total === 0) return `${when} · sem atividade`
  const parts: string[] = []
  if (data.katas > 0) parts.push(`${data.katas} kata${data.katas !== 1 ? 's' : ''}`)
  if (data.courses > 0) parts.push(`${data.courses} aula${data.courses !== 1 ? 's' : ''}`)
  if (data.books > 0) parts.push(`${data.books} livro${data.books !== 1 ? 's' : ''}`)
  return `${when} · ${parts.join(', ')}`
}
```

```ts
export interface ExerciseLite { title: string; slug: string; difficulty: string }
export interface ResumeLite { exercise: ExerciseLite; passed_count: number; total_count: number }
export type ModeKey = 'rankup' | 'warmup' | 'practice'
export interface NextAction {
  kind: 'resume' | 'start'
  slug: string; title: string; difficulty: string
  progress: string | null
}

export const MODE_LABEL: Record<ModeKey, string> = { rankup: 'Rank Up', warmup: 'Aquecimento', practice: 'Praticar' }

const ORDER: Record<string, number> = {
  '8kyu': 0, '7kyu': 1, '6kyu': 2, '5kyu': 3, '4kyu': 4, '3kyu': 5, '2kyu': 6, '1kyu': 7,
}

// hardest -> rankup, easiest -> warmup, middle -> practice (same rule as the desktop dashboard)
export function pickModes<T extends ExerciseLite>(exercises: T[]): Record<ModeKey, T | null> {
  if (exercises.length === 0) return { rankup: null, warmup: null, practice: null }
  const sorted = [...exercises].sort((a, b) => (ORDER[b.difficulty] ?? 0) - (ORDER[a.difficulty] ?? 0))
  return {
    rankup: sorted[0] ?? null,
    warmup: sorted[sorted.length - 1] ?? null,
    practice: sorted.length >= 3 ? sorted[1] : sorted[1] ?? null,
  }
}

export function distinctModeCount(exercises: ExerciseLite[]): number {
  const modes = pickModes(exercises)
  return new Set(Object.values(modes).filter((e): e is ExerciseLite => e !== null).map(e => e.slug)).size
}

export function pickNextAction(resume: ResumeLite | null, exercises: ExerciseLite[], mode: ModeKey = 'rankup'): NextAction | null {
  if (resume && resume.total_count > 0 && resume.passed_count < resume.total_count) {
    const { slug, title, difficulty } = resume.exercise
    return { kind: 'resume', slug, title, difficulty, progress: `${resume.passed_count}/${resume.total_count} testes` }
  }
  const chosen = pickModes(exercises)[mode]
  if (!chosen) return null
  return { kind: 'start', slug: chosen.slug, title: chosen.title, difficulty: chosen.difficulty, progress: null }
}
```

```ts
import { useCallback, useEffect, useState } from 'react'

export type SlotStatus = 'loading' | 'ready' | 'error'
export interface Slot<T> { status: SlotStatus; data: T | null; retry: () => void }

// `load` must be a stable reference (a module-level function).
export function useSlot<T>(load: () => Promise<T>): Slot<T> {
  const [state, setState] = useState<{ status: SlotStatus; data: T | null }>({ status: 'loading', data: null })
  const [tick, setTick] = useState(0)

  useEffect(() => {
    let alive = true
    setState(s => ({ status: 'loading', data: s.data }))
    load()
      .then(data => { if (alive) setState({ status: 'ready', data }) })
      .catch(() => { if (alive) setState({ status: 'error', data: null }) })
    return () => { alive = false }
  }, [load, tick])

  const retry = useCallback(() => setTick(t => t + 1), [])
  return { ...state, retry }
}
```
