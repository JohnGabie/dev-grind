DevGrind

A backend learning platform built for one person.

DevGrind is a personal study platform built for João — a single user with ADHD learning Python, FastAPI, SQL, and HTTP to fully understand his own production project (ZionHub), without depending on AI to navigate his own code.

Cloudflare Workers Pyodide · Python in-browser Adaptive AI Agent Monaco Editor

Core Concept

Two separate learning tracks

DevGrind has two distinct modes of learning, each designed for a different cognitive state and goal.

Track 01

Courses

Structured, linear progression — Duolingo style

Content is built on top of the 21 books in study-backend/books/. Each lesson is a book chapter with theory and practical exercises attached. The learner advances module by module, phase by phase.

Linear roadmap Chapter-linked exercises Phase progression 21 books as source

Track 02

Practice

Adaptive kata engine — CodeWars style

Standalone exercises with real code execution via Pyodide (Python in the browser). An AI agent analyses performance by concept and calibrates the next batch. Focus: real backend problems — HTTP, SQL, FastAPI. Not algorithm puzzles.

Pyodide execution Adaptive batches Concept tracking kyu/honor system

CodeWars is context, not content

The CodeWars public API is used only to read João's completed katas (user: JohnGabie) to understand his current level and avoid repeating topics he already knows. No exercises are copied from CodeWars — all content is generated by the adaptive agent based on the study books and the personal roadmap.

Intelligence

How the adaptive agent works

The agent does NOT validate exercises in real time. It operates in asynchronous cycles every 6 hours.

1

User solves exercises

Pyodide validates code in the browser. Result (passed / partial / failed) plus time spent, concepts, and cursor heatmap are saved to the database via POST /submissions.

2

Agent fires every 6 hours

Claude Code /schedule runs agent/daily_prompt.md. The agent reads analytics, the user profile, the roadmap, and recent chat messages.

3

Gap analysis

Which concepts have a pass rate below 60%? The agent requires at least 2 independent signals (e.g., low pass rate + repeated chat questions) before acting on a gap. Signal quality over signal quantity (ADR-019).

4

Generates calibrated exercises

Writes 1–3 JSON exercises into platform/backend/app/exercises/generated/YYYY-MM-DD/, then calls POST /exercises/load. Quantity scales with recent activity. Saves a brief insight to agent/last_insight.json.

5

Roadmap gates progression

The agent amplifies learning within the current roadmap module — it does not skip modules or change what João is learning. The roadmap is the spine; the agent adjusts density and difficulty within it (ADR-015).

Concept taxonomy tracked per exercise

python:types python:functions python:async python:oop http:methods http:status-codes http:headers http:rest sql:select sql:joins sql:aggregations sql:transactions fastapi:routing fastapi:pydantic fastapi:auth fastapi:middleware arch:separation-of-concerns arch:error-handling arch:naming

Signal quality thresholds (ADR-019)

SignalValid ifDiscarded if
time_on_line 5s – 300s per line <5s (accidental scroll) or >300s (user left)
time_spent 60s – 7200s <60s (quick test) or >7200s (abandoned)
cursor_heatmap ≥ 3 distinct lines visited <3 lines (editor barely used)
chat_messages ≥ 10 characters Test messages, "oi", isolated "?"
concept pass rate ≥ 5 submissions on that concept <5 submissions (insufficient sample)

Calibration logic

# Agent cycle — quantity calibration
if submissions_last_3_days == 0:
    generate(1, difficulty="easy")      # re-engagement
elif submissions_today >= 5:
    generate(3, difficulty="escalated")  # high activity
else:
    generate(2, focus="gap_concepts")   # normal day

Anti-patterns

What this platform is NOT

🚫

Not algorithm kata

No sorting algorithms, no binary search, no Leetcode-style puzzles. Every exercise is a real backend development scenario.

🚫

Not real-time AI grading

Pyodide validates objectively (pass/fail). The AI runs in async cycles — it never grades individual answers in real time.

🚫

Not a generic platform

Built for one person. The curriculum maps exactly to João's production project (ZionHub) and personal roadmap.

🚫

No Anthropic key in backend

The daily agent runs as a Claude Code /schedule session — it uses João's existing account with no separate API key in the Worker.

🚫

No display fonts

JetBrains Mono is the only font, used everywhere in weights 400–800. No Syne, no Outfit, no "AI startup aesthetic."

🚫

No treadmill progression

The agent fills gaps but doesn't control the roadmap. A fixed curriculum ensures João always advances — the AI just adjusts the pacing.
